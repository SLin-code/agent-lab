# 课程编写指南

## 1. 创建课程包

```bash
pnpm new:lesson <domain-id> <lesson-slug> "中文标题"
```

脚手架会创建：

- `meta.ts`：纯数据课程元信息，由 Catalog eager 读取。
- `index.tsx`：默认导出页面组件，进入路由时 lazy 加载。
- `Lesson.tsx`：课程正文与章节编排。
- `labs/`：本课专属的交互、固定数据和状态。

课程目录的 `meta.ts` 与 `index.tsx` 必须成对存在。不要手动修改中央 manifest 或路由表。

## 2. 先定义判断，再设计页面

在 `meta.ts` 中填写：

- 一句话摘要与一个核心主张；
- 两到四个带稳定 ID 的可观察学习目标；
- 交互清单，以及每个交互覆盖的目标 ID；
- 受众、稳定性、标签和复核日期；
- 带稳定 ID 的事实主张，以及每个来源支持的主张 ID。

先写清学习者最终应该能作出的判断，再确定交互。对过程型概念，回答：六步 Run 中本课聚焦哪一步、只改变哪个变量、唯一分叉是什么。不要从“做一个复杂仪表盘”开始。

`lesson.revision` 是完成记录版本。只改错别字时保持不变；如果核心判断或交互含义发生变化，递增 revision。`lesson.id` 与 `lesson.slug` 发布后保持稳定。

## 3. 使用标准教学节奏

推荐顺序：

1. 用真实任务提出一个问题。
2. 用静态对比建立最小心智模型。
3. 展示固定 Run：目标 → 看见 → 决定 → 行动 → 观察 → 继续 / 停止。
4. 在反馈前让学习者作出一次选择。
5. 只改变一个变量，揭示一处分叉和对应证据。
6. 用反例、边界或常见误区复盘。
7. 以 `LessonTakeaway` 收束；页面外壳添加 Sources、Completion 与下一课。

通常使用四到六个实质章节。课程自身不要重复实现 Hero、来源、进度或下一课导航。

## 4. 按职责边界协作

- 一个课程包是最小交付单元，文案、元数据、数据和专属 Lab 一起提交。
- 贡献者通常只修改所属 `domain`；类型、共享组件和样式是跨方向改动。
- 课程内容与平台重构尽量拆开，方便不同方向的人或 Agent 并行审查。
- “输出即学习”描述贡献者的研究与建设过程，不得转译成学习者作业框。

## 5. 复用规则

- 编辑结构：`components/lesson`。
- Lab 标题与外框：`components/lab/LabFrame`。
- 六步路径呈现：`components/lab/MinimalRun`。
- 固定在第三步二选一、随后比较两条结果：`components/lab/MinimalRunExperiment`。课程只填写声明式实验数据，不复制推进与重置逻辑。
- 本课专属的数据与状态：课程自己的 `labs/` 目录。
- 至少被两门课程验证的其他语义交互：`labs/shared`。

共享的是教学与状态语义，不是视觉相似性。二分支原语只适合“一个变量、两个选择、固定决策点”；不要把它扩成万能 Graph 或问答引擎。

## 6. 交互规则

- 一次只改变一个变量，只揭示一个可归因的分叉。
- 默认手动推进，不自动播放；每个状态只保留一个主要操作。
- 重置是次要操作，但始终可达。
- 未来步骤只显示名称；历史 Trace 默认折叠。
- 静态对比足够时，不增加按钮、步骤或状态机。
- 禁止 `textarea`、`contenteditable` 和任何长篇文字输入。
- 优先使用选择、切换、排序、逐步运行、重放与前后对比。
- 展示决策摘要、行动、观察、证据和状态事实，不展示隐藏思维链。
- 不用伪代码承担核心解释。
- 保持原生键盘顺序、至少 44px 触控目标和非颜色单一编码。
- 在 320px 宽度下重排路径，不缩小到不可读；尊重 reduced motion。

## 7. 提交前检查

- 元数据只存在于 `meta.ts`，`index.tsx` 只提供默认页面导出。
- ID、slug、domain 与目录一致；`lesson.revision` 为正整数。
- 每个学习目标至少由一次交互覆盖。
- Run 六步语义一致，本课变量与分叉能用一句话说明。
- 页面没有 `textarea`、`contenteditable` 或长文本提交门槛。
- 每个事实来源都说明它支持什么。
- 每条 Lab 分支都可到达、可重置，并支持键盘操作。
- 桌面与 320px 移动端表达相同含义。
- `pnpm typecheck` 和 `pnpm build` 均通过。
