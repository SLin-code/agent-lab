# 课程编写指南

## 1. 创建课程包

```bash
pnpm new:lesson <domain-id> <lesson-slug> "中文标题"
```

示例：

```bash
pnpm new:lesson context context-budget "给 Agent 一份有限的上下文预算"
```

命令不会覆盖已有目录。新课程会被自动发现，不要手动修改 `catalog.ts`。

脚手架会创建四个边界：

- `meta.ts`：默认导出 `defineLessonMeta(...)`；Catalog 会 eager 读取它。
- `index.tsx`：默认导出课程页面组件；Catalog 只保留 loader，进入课程路由时才加载。
- `Lesson.tsx`：课程正文与章节编排。
- `labs/`：本课专属的交互、固定数据和状态。

保持 `index.tsx` 很薄，不要把元数据搬回其中。`meta.ts` 必须是纯数据，不能导入页面组件、课程 Lab 或访问 `window`。课程目录的 `meta.ts` 与 `index.tsx` 必须成对存在；新增文件后无需维护中央注册表。

## 2. 先定义输出，再编写章节

在 `meta.ts` 中填写：

- 一句话摘要与一个核心主张；
- 两到四个带稳定 ID 的可观察学习目标；
- 交互清单，以及每个交互覆盖的目标 ID；
- 受众、稳定性、标签和复核日期；
- 学习者最终要完成的具体作品；
- 输出覆盖的目标 ID、迁移情境，以及带稳定 ID 的自检标准；
- 带稳定 ID 的事实主张，以及每个来源支持的主张 ID。

`lesson.output` 不能只是“总结本课”。它应要求学习者运用概念作出判断、组织证据或设计系统，并让另一位读者能够检查结果。

`lesson.output.revision` 是完成记录的契约版本。只改错别字时保持不变；如果修改任务含义、增加或删除自检标准，必须递增 revision。旧草稿仍会保留，但旧完成标记不会越过新版输出门槛。

想法或交互尚未完成时保持 `draft`；另一位贡献者已经可以端到端体验时改为 `review`；满足学习契约后才使用 `ready`。开发环境可以用直接路由预览三种状态，生产环境只公开 `ready` 课程。

## 3. 使用标准教学节奏

推荐顺序：

1. 用同一个任务对比两种系统设计。
2. 用自然语言和紧凑可视化建立心智模型。
3. 在反馈前让学习者预测、判断或分类。
4. 逐步运行过程，并展示状态如何变化。
5. 引入失败、边界或反例。
6. 用对比和常见误区复盘。
7. 以 `LessonTakeaway` 收束；页面外壳会添加 Output、Sources 和 Completion。

通常使用四到七个实质章节。页面外壳负责 Hero、来源、学习输出和完成区域，课程自身不要重复实现。

## 4. 按职责边界协作

- 一个课程包是最小交付单元，文案、元数据、数据和专属 Lab 应一起提交。
- 贡献者通常只修改所属 `domain`。跨方向的类型、共享组件和样式改动需要额外审查。
- 不要为了当前课程把案例逻辑塞进共享层，也不要让共享组件导入具体课程。
- 课程内容与平台重构尽量拆开，方便不同方向的人或 Agent 并行审查和合并。

## 5. 复用规则

- 编辑结构：`components/lesson`。
- Lab 标题与外框：`components/lab/LabFrame`。
- 至少被两门不同课程验证的语义交互：`labs/shared`。
- 本课专属的数据与状态：课程自己的 `labs/` 目录。

新交互一律从课程自己的 `labs/` 开始。第二门课出现相同需求时，先分别确认两门课的教学行为、可访问性契约和状态语义；只有三者都相同，才在接入第二个消费者的同一次改动中提取到 `labs/shared`。两个页面实例、同一课的两个章节和未来规划都不算真实消费者，也不要让第二门课直接导入第一门课的 `labs/`。

不要因为两个界面都长得像卡片就创建通用组件。共享的是教学与状态语义，不是视觉相似性。

## 6. 交互规则

- 先写清交互要帮助学习者观察的状态变化、因果关系或证据差异，再决定界面形式。
- 静态对比或带注释的图已经足够时，不增加按钮、步骤或状态机。
- 点击后只展开下一段文案不算有效交互；操作必须产生有教学意义的反馈。
- 默认手动推进，不自动播放。
- 每个状态只保留一个主要操作，并始终提供重置。
- 首屏在尚未操作时也必须传达有用信息。
- 展示决策摘要、行动、观察、证据和状态事实，不展示或仿造隐藏思维链。
- 不用伪代码承担核心解释，优先使用交互流程、状态转移、Trace 播放或故障对比。
- 保持原生键盘顺序和至少 44px 的触控目标。
- 颜色必须配合文字或形状，不能单独承担含义。
- 在 320px 宽度下重排 Graph，不要把标签缩到不可读。
- 尊重 reduced motion，并为视觉流程提供文字顺序。

## 7. 提交前检查

- 元数据只存在于课程的 `meta.ts`，且不依赖页面或浏览器环境。
- `index.tsx` 只提供页面组件的默认导出，能够被 Catalog 懒加载。
- `meta.ts` 与 `index.tsx` 成对存在，ID、slug 和 domain 与目录一致。
- 学习目标、交互、输出、主张和来源之间的 ID 引用完整；没有 TODO 或占位内容被标为 `ready`。
- 页面只有一个 H1，由外壳提供；H2/H3 层级正确。
- 每个学习目标都对应一次操作或一项学习输出。
- 每个事实来源都说明它支持什么。
- 每条 Lab 分支都可到达、可重置，并支持键盘操作。
- 桌面与移动端表达相同含义。
- `pnpm typecheck` 和 `pnpm build` 均通过；两者会先执行 `pnpm validate:content`，不要绕过 Catalog 的元数据校验。
