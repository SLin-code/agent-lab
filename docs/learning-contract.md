# 学习契约：输出即学习

“输出即学习”不是完成一次点击，也不是把课后作业附在文章末尾。它要求学习者把判断、证据和边界整理成一个可检查的作品。只有理解被表达出来，假设才会暴露，反馈才有明确对象。

每门课遵循同一个闭环：

```text
Orient → Predict → Act → Observe → Explain → Output → Review
```

- **Orient（定向）**：用一个真实情境提出核心问题。
- **Predict（预测）**：在揭示答案前，先让学习者作出判断。
- **Act（操作）**：改变输入、决策、路径或系统条件。
- **Observe（观察）**：展示由此产生的路径、状态、证据或失败。
- **Explain（解释）**：把观察结果连接到概念及其适用边界。
- **Output（输出）**：形成判断、带注释的 Trace、Graph、设计、评估或实现。
- **Review（复查）**：按照明确标准自检，使作品可被他人理解和复用。

交互负责让概念发生，输出负责证明学习者能独立使用概念。两者不能互相替代。

交互本身不是学习目标。只有当学习者的预测或操作会揭示一个值得观察的状态变化、因果关系、证据差异或失败边界时，才应该使用交互。如果静态对比、带注释的图或一组并列 Trace 能传达同样的理解，就使用更简单的表达。

设计交互前必须能回答三个问题：

1. 学习者在看到结果前要作出什么预测或选择？
2. 这个操作会改变什么状态、路径或证据？
3. 学习者能从变化中得出什么仅靠翻页或展开文案得不到的判断？

如果第三个问题没有明确答案，就不应把内容包装成 Lab。

## `ready` 课程的最低要求

一门课只有同时满足以下条件，才可以标记为 `ready`：

1. 有一个清晰主张和两到四个可观察的学习目标。
2. 至少一次在解释前要求预测、判断或操作。
3. 反馈明确指出哪些证据改变了结果。
4. 交互可以重置，并从确定的初始状态开始。
5. 定义一个 `lesson.output` 作品及明确的自检标准。
6. 提供一个新情境，让学习者迁移刚学到的判断方法。
7. 事实主张与来源对应，并记录核验日期。

最终作品应小到能在本课内完成，又完整到无需旁观学习过程也能被检查。当前作品保存在学习者的浏览器中，并可复制到其他地方；未来的账号或作品集能力应继续使用这套内容契约。

## 各知识方向适合的输出

- Foundations：判断一个系统的类型，并说明控制权证据。
- Behavior & Tools：写出工具契约，并判断一次调用是否安全、可验证。
- Context：分配上下文预算，并解释每项信息为何进入模型视野。
- Protocols：画出能力、协议参与方与信任边界。
- Harness：设计权限、工具、检查点和恢复行为。
- Loop：标注一次 Trace，并选择重试、停止、升级或移交。
- Graph：构建状态图，并说明每条转移由谁决定。
- Reliability：设计评估集，并解释失败聚类。
- Capstone：交付一个带证据、限制和运行手册的 Agent System。
