# 学习契约：低负担地看见一次 Run

“输出即学习”是 AgentPath 的内容生产方式：建设者通过研究、解释、实现、审查和发布课程来完成学习。它不是面向学习者的作业制度，更不意味着每一课都要填写一段长文字。

学习者需要的是一个稳定、可迁移的心智模型。涉及过程的课程共享同一组 Run 语义：

```text
目标 → 看见 → 决定 → 行动 → 观察 → 继续 / 停止
```

- **目标**：当前任务是什么，什么状态才算完成。
- **看见**：此刻进入工作视野的事实、状态与约束。
- **决定**：基于当前证据选择一个可解释的下一步。
- **行动**：Host 或工具真正做了什么。
- **观察**：环境返回了什么可核验的新事实。
- **继续 / 停止**：完成标准满足了吗；下一轮是否必要。

交互的目的不是增加点击量，而是让因果发生在眼前。循环、闸门、预算、恢复路径可以使用完全不同的视觉拓扑；只有比较实验才采用“只改一个条件 → 对比一处分叉”的节奏。每个状态只提供一个主要动作，已发生的详细 Trace 默认折叠。

## 什么时候值得交互

设计交互前必须能回答三个问题：

1. 哪个关系、状态变化或因果，仅靠正文不容易看见？
2. 学习者需要推进、选择、重放还是只看一张带注释的图，才能看清它？
3. 哪一处可见变化能帮助学习者建立可迁移的判断？

如果学习目标是比较因果，尽量一次只改变一个变量；如果目标是读懂一次循环或时间线，就让推进过程本身揭示状态变化。如果静态对比或带注释的图更清楚，就不要包装成 Lab。

## 输入负担

- 禁止在课程中使用 `textarea`、`contenteditable` 或长篇问答框。
- 不把复制模板、填写报告、写设计文档作为完成课程的门槛。
- 优先使用二选一、排序、开关、逐步运行、重放与前后对比。
- 迁移学习通过切换一个新情境或变量完成，而不是要求学习者重新写一篇答案。

## `ready` 课程的最低要求

一门课只有同时满足以下条件，才可以标记为 `ready`：

1. 有一个清晰主张和两到四个可观察的学习目标。
2. 至少一个与概念匹配、可交互或可重放的可视演示；只有当“作出判断”本身是学习目标时，才要求预测或选择。其他章节若用静态图更清楚，就保持静态。
3. Run 的目标、观察、决定、行动与继续/停止关系可辨认，但视觉拓扑不要求相同。
4. 比较实验一次只改变一个核心变量，并清楚标出由它造成的分叉。
5. 反馈指出哪些环境证据改变了结果。
6. 交互可重置，并从确定的初始状态开始。
7. 不要求任何长文本输入；完成进度不依赖提交作品。
8. 事实主张与来源对应，并记录核验日期。

## 各方向优先观察什么

- Foundations：谁决定下一步；观察是否改变路径。
- Behavior & Tools：Host 是否放行动作；环境能否证明副作用。
- Context：哪项证据进入视野；缺口让 Run 继续还是停止。
- Protocols：消息由谁发送；信任边界在哪里改变。
- Harness：运行何时暂停；检查点能否支持恢复。
- Loop：重试、停止、升级或移交由哪条证据触发。
- Graph：状态转移由谁决定；哪条边在运行时被选择。
- Reliability：哪个失败信号触发评估与修正。
- Capstone：多个边界如何在一条可观察 Run 中协同。
